# PR #13 UI 최소 수정 검토 — 적용하지 않은 제안

검토 기준: a8745c1cb462ff6ec55b0781dcfc0d5be7007d4d, 앱0.3.7/code13. [PR #13](https://github.com/Notice-Me/notice-me/pull/13)의 MainActivity·activity_notice_feed.xml·styles를 읽었으며 수정/병합/제출 APK 포함은 하지 않았다. 이후 팀원 commit은 별도 재검토 대상이다. 아래는 **코드와 치수 계산에 근거한 정적 분석**이며 400dp 미만 기기의 화면 측정 결과가 아니다.

## 2×2 버튼

`windowWidth < 400`이면 actions.chunked(2)로 두 행을 만드는 분기는 이미 존재한다. 두 행을 추가하는 코드가 없다고 진단하면 안 된다. 문제 후보는 실제 내부 너비와 높이다.

- 400dp 창에서는 한 행4개다. 좌우20dp padding·간격6dp×3을 빼면 버튼당85.5dp, 버튼 좌우8dp를 빼면 글자 영역69.5dp다. 21sp의 '다시 듣기'가 한 줄에 들어가는지는 실제 font/scale로 측정해야 한다. 399→400dp 경계에서2행이 갑자기1행이 되는 부분을 확인한다.
- 399dp에서는 버튼당176.5dp라 너비는 넓지만, 최소72dp×2행+간격6dp+재생 제목/패딩이 하단 높이를 크게 쓴다. 짧은 분할 창에서는 body가 거의 안 보일 수 있다.
- 최소 제안: 창 전체 너비 하나 대신 player의 **실제 가용 너비**와 글자 측정값/패딩/간격으로 행 수를 정한다. 화면 높이가 부족할 때는 재생 제목을1줄로 줄이거나 여백을 조절하는 방안을 먼저 검토한다. 공식 차량 터치 규격 확인 없이 버튼을 임의로 작게 만들지 않는다.
- 크기 변경 때 재배치한다면 기존 Button parent를 제거한 후 다시 추가하고 동작 listener/state는 유지해야 한다. 처음 생성 때만 사용하는 현재 코드를 그대로 반복 호출하면 parent 충돌이 생길 수 있다.

## 카드·여백·긴 제목

상단/본문/플레이어는 같은 root padding을 공유한다. header는 별도 고정이고 카드·설정은 body 안에 있다. 최소 제안은 카드 폭/여백의 공통 기준을 유지하고 짧은 제목·긴 제목·다중 출처·빈 brief에 같은 좌우 정렬을 적용하는 것이다. 창 경계599/600·1199/1200dp에서 글자·padding이 동시에 변하므로 실측한다.

제목 maxLines2+END, 요약 maxLines3+END, URL maxLines1+END는 구현돼 있다. 줄바꿈 기능 자체가 없다는 문제는 아니다. 한글 장문·공백 없는 영문/URL·emoji와 글자 배율1.0/1.3에서 두 줄 제한/말줄임·원문 링크 동작을 확인한다. 현재 evidence로 그 조합들이 정상이라고 단정하지 않는다. [TextView 공식 설명](https://developer.android.com/reference/android/widget/TextView).

## 고정 플레이어와 분할 창

XML은 세로 LinearLayout의 header → 높이0/weight1 ScrollView → wrap_content player다. overlay로 겹치는 구조는 아니므로 '고정 플레이어가 무조건 카드를 덮는다'고 단정할 수 없다. 다만 header+player가 창 높이를 대부분 쓰면 ScrollView의 가용 높이가 부족해지고, 시스템 bar/키보드 inset 처리와 마지막 카드까지 스크롤 가능한지가 중요하다.

최소 제안은 먼저 측정한 header/player/scroll 높이와 inset을 기록하고, compact-height에서 제목/여백을 조정해 충분한 스크롤 영역을 확보하는 것이다. 화면 전체 높이로 계산하거나 가짜 spacer를 먼저 추가하지 않는다. [Android 분할 창 안내](https://developer.android.com/develop/ui/views/layout/support-multi-window-mode).

팀원 인수표: 폭320/360/399/400/600dp, 짧은 높이300/480dp와 일반 높이, fontScale1.0/1.3, 설정 열림/닫힘, 긴 제목, 마지막 카드까지 스크롤, 재생 중 버튼4개 접근. 이 표는 앞으로 실행할 테스트이며 통과 기록이 아니다. UI 완료 통보 후 새 commit으로 두 flavor·release 재빌드/서명·실제 조작을 검증하고 버전/README/hash를 갱신한다.
