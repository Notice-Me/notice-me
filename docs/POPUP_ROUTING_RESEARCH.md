## 공식 공지 기반 수동 등록 절차와 한계

기존 [manual-events.template.json](examples/manual-events.template.json), [popups.py](../server/app/popups.py)를 재사용한다. 자동 크롤러·실제 행사 예시는 추가하지 않았다.

1. 브랜드/공식 주최사/운영사/입점 시설의 원문 공지를 확보한다. 포트폴리오·검색 요약·제3자 후기만으로 확정하지 않는다. 공식 도메인 소유 관계도 검토자가 확인한다.
2. 행사명·실제 운영 주체·정확한 장소/주소·확인된 WGS84 좌표·KST 시작/종료·현재 취소/변경 여부를 대조한다. 빈 필드를 추정으로 채우지 않는다. 공식 URL과 확인 시각/근거를 남긴다.
3. 데이터 이용조건과 출처 표시 범위를 확인한다. 링크/사실 메타데이터 확인과 본문·이미지·TTS 권리는 분리한다. 불명확하면 LICENSE_UNVERIFIED, 원문 본문은 저장하지 않는다. 현재 LIVE 음성은 계속 날씨만 허용한다.
4. 기존 수동 JSON의 confirmed, confirmation_evidence, organizer_confirmed_at, starts_at, expires_at, venue, 좌표, LIVE/VERIFIED 요건을 충족할 때만 검토 후 등록한다. 실제 자동차 이동시간 검증 전에는 LIVE 추천 제외가 계속 적용된다.
5. 시연 직전 공식 공지에서 취소·변경을 재확인한다. **현재 수동 importer는 URL 소유권을 자동 검증하지 않고 검토자의 확인에 의존하며, 취소 상태/주소 필드도 없다. 파일에서 confirmed=false로 바꾸는 것만으로 과거 DB 행이 자동 격리되지 않는다.** 실제 등록을 늘리기 전에 취소/격리 절차를 P1으로 마련해야 한다. 기존 DB를 임의로 지우지 않는다.

REST 키/서비스 설정이 필요하며 공식 GET `/v1/directions`의 좌표 순서는 **경도,위도**, summary.duration 단위는 **초**다. 향후 성공 응답·경로 result_code·좌표·duration 유효성 확인 후에만 분으로 변환하고 provider/checked_at을 기록해야 한다. 오류·할당량·미탐색·시간 미확인은 UNVERIFIED로 차단한다.

현재 RoutingProvider.assess는 동기 인터페이스다. httpx 비동기 수집처럼 붙이려면 async 선계산 후 평가 주입 또는 인터페이스 변경 검토가 먼저다. 실행 중 event loop에 asyncio.run을 넣는 방식은 채택하지 않는다. 후보를 관심사/유효성으로 먼저 좁히고 호출 상한·timeout·재시도 예산을 설계하는 P1 후속 작업으로 분리했다. 제안 시연 예산은 전체 최대5회이며 공식 할당량과는 별개인 자체 제한이다. 실패 시 임의 시간/직선거리 환산 금지. 정밀 위치·목적지·경로를 DB/접근 로그에 남기지 않으며 캐시가 필요하면 공급자 약관과 일시 메모리 범위를 먼저 합의한다.

## 위치·목적지와 앱 인계

현재 위치 기반 점수, 내비 활성 시 제공된 목적지/경로점 우선 점수, ETA의 음성 재생 예산은 기존 구현을 유지했다. 경로점이 없으면 생성하지 않는다. 목적지 ETA는 행사장까지의 운전시간 증거가 아니며 실제 RoutingProvider가 없으므로 LIVE 행사60분 조건 차단을 유지한다.

앱 담당자에게 전달할 현재 필드와 주소/공식 URL/장소 검증의 결손, 향후 nullable navigation_target 제안은 [계약 검토](INTEREST_CONTRACT_REVIEW.md)에 정리했다. 새 응답 DTO와 실제 길안내 명령은 이번 미구현이다. 장소가 불명확한 항목은 향후 eligible=false 기본값으로 다루자는 제안이며 기존 VERIFIED/tts_eligible를 길안내 허가로 읽으면 안 된다.
